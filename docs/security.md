# Security and TLS boundary

- Product scripts install no TLS certificates, keys, issuers, ingress controllers or public routes. An operator must provide HTTPS at the configured `url` and a trusted route to ClusterIP port 9091. Configuring an HTTPS URL alone does not create a public endpoint.
- LDAP and SMTP are external. LDAPS or StartTLS and verified server certificates are mandatory; a private CA bundle can augment trust. Never substitute `skip_verify` or plaintext transport for fixing a CA/hostname problem. Lab fixtures are separate from product deployment.
- Authelia runs as UID/GID 1000 with a read-only root filesystem, no privilege escalation, dropped capabilities, RuntimeDefault seccomp and no ServiceAccount token. Only `/data` and `/tmp` are writable. SQLite and encrypted factor data live on the PVC.
- Passwords are hidden in interactive input, kept in private JSON (0600), sent to Kubernetes through stdin, and mounted from `authelia-secrets`. No credential-bearing command arguments, shell sourcing, ConfigMap passwords, Secret output or generated public secrets are used. Kubernetes Secrets are not encryption-at-rest by themselves: protect kubeconfig/RBAC and enable cluster datastore encryption under your cluster's policy.
- Generated session/storage keys are preserved. Missing/weak existing keys fail closed. Reinstall is not credential rotation. Never regenerate a storage key beside existing data.
- Local config directories must be private and administrator-owned; never run the scripts with a config/lock path writable by another user. One local lock does not coordinate multiple admin hosts.
- Default authorization is deny; the single allowed domain/group requires two factors. LDAP service-account bind success is not user authentication. The submitted user's password is checked by a live LDAP bind. `one_factor` is an explicit reduction in policy, not MFA.
- LDAP implementation, disabled-account filtering and account lifecycle are operator responsibilities. FreeIPA OTP bind controls are **not** proven by OpenLDAP QA. Authelia-managed TOTP enrollment is distinct from reusing an existing FreeIPA OTP token.
- Sessions use process memory and secure cookies; remember-me is disabled. Restart logs everyone out. A live portal can generate activity, so test inactivity with the page closed/blank, not an actively polling portal.
- Direct application access must not bypass your proxy's authorization boundary. This product exposes only ClusterIP but does not impose a network policy automatically because proxy/LDAP/SMTP locations vary. Apply a reviewed NetworkPolicy and firewall rules for your topology, restrict port 9091 to trusted callers, and protect downstream applications separately. Do not trust identity headers sent directly by clients.
- `examples/forward-auth.yaml` is an operator-applied example, not an automatically installed middleware or a Hermes integration. Proxy sanitization and routing must be verified end to end.
- Backup/recovery is operator-owned with Velero; this installer has no backup/restore feature and does not install or configure Velero. Protect PVC contents and matching encryption Secrets as sensitive state.

Report security defects privately to the repository maintainer. Never attach real config files, kubeconfigs, passwords, session cookies, TOTP seeds or raw debug dumps to public issues.
